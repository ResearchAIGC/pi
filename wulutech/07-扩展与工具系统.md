# 07 — 扩展与工具系统

> 源码：`packages/coding-agent/src/core/extensions/` / `core/tools/` / `core/skills.ts` / `core/prompt-templates.ts`
> 关键文件：`extensions/types.ts`（1500+ 行，30+ 事件类型）、`extensions/loader.ts`、`extensions/runner.ts`、`extensions/wrapper.ts`

---

## 1. 扩展（Extension）是什么

扩展是 **TypeScript 模块**（`export default function(pi: ExtensionAPI) { ... }` 形式），在 Pi 启动/重载时被发现与加载，能：

- 订阅 30+ 生命周期事件（`on("tool_call", ...)` 等）
- 注册 LLM 可调用工具（`pi.registerTool({...})`）
- 注册斜杠命令、快捷键、CLI flag（`pi.registerCommand/registerShortcut/registerFlag`）
- 通过 `ctx.ui` 请求对话框、自定义编辑器、覆盖 footer/header、注入 widget
- 注册消息/Entry 渲染器与 Markdown 转换器

扩展是 Pi 实现“自扩展（self-extensible）”的核心：**Gondolin 容器化、Llama 本地模型、自定义 Provider、项目专属命令** 全由扩展实现，而非 fork 代码。

## 2. 发现与加载（`extensions/loader.ts`）

### 2.1 发现路径

`discoverAndLoadExtensions()` 扫描（按优先级）：

1. CLI 显式 `-e <path>` 指定的路径
2. `~/.pi/agent/extensions/*`（全局扩展，每个子目录一扩展，含 `package.json`）
3. 项目内 `.pi/extensions/*`（若存在，且项目已 trust）
4. `packages/coding-agent/examples/extensions/*`（示例扩展，如 `with-deps` / `custom-provider-anthropic` / `sandbox` / `gondolin`）

扫描结果经 `ResourceLoader`（`core/resource-loader.ts`）去重与校验（`ResourceCollision` / `ResourceDiagnostic`）。

### 2.2 加载

```ts
loadExtensions(factories: ExtensionFactory[]) → { runner: ExtensionRunner, diagnostics }
loadExtensionFromFactory(factory, sourceInfo) → { extension, diagnostics }
```

一个扩展模块的默认导出可为：

- `ExtensionFactory = (pi: ExtensionAPI) => void | Promise<void>`（函数式，推荐）
- `Extension = { name, setup(pi) }`（对象式）
- `InlineExtension`（内联工具，用于 SDK 的 `customTools`）

加载时传入 `SourceInfo { path, packageName?, version? }` 用于诊断与热重载。

### 2.3 SDK 内联

通过 `createAgentSession({ customTools: [defineTool({...})] })`，可不走文件扫描直接注入工具；`createAllToolDefinitions` 等工厂在 `AgentSession._buildRuntime()` 中与扩展工具合并。

## 3. ExtensionAPI（`extensions/types.ts:1252-1461`）

### 3.1 事件订阅（20+ 事件）

```ts
pi.on("project_trust", handler)          // 项目信任决策（可 remember）
pi.on("resources_discover", handler)     // 追加 skill/prompt/theme 路径
pi.on("session_start", handler)          // 会话开始/重载/new/resume/fork
pi.on("session_before_switch", handler)  // 可 cancel
pi.on("session_before_compact", handler) // 可 cancel 或覆盖 summary
pi.on("context", handler)                // 每次 LLM 调用前，可注入消息
pi.on("before_provider_request/headers", handler) // 可替换 payload / 改 headers
pi.on("before_agent_start", handler)     // 可注入 CustomMessage / 覆盖 systemPrompt
pi.on("agent_start/end/settled", handler)
pi.on("turn_start/end", handler)
pi.on("message_start/update/end", handler) // message_end 可替换 message
pi.on("tool_execution_start/update/end", handler)
pi.on("tool_call", handler)              // 可 block / 改 input
pi.on("tool_result", handler)            // 可改 content/details/isError
pi.on("model_select", handler)
pi.on("input", handler)                  // 可 transform/handled 输入
pi.on("user_bash", handler)              // 可接管 ! 命令执行
```

所有处理器签名 `ExtensionHandler<E,R> = (event: E, ctx: ExtensionContext) => Promise<R|void>|R|void`，`ctx` 为扩展上下文（见 §3.3）。

### 3.2 注册

```ts
pi.registerTool({ name, description, parameters: Type.Object({...}), execute, renderCall, renderResult })
pi.registerCommand(name, { description, handler: (args, ctx: ExtensionCommandContext) => void })
pi.registerShortcut(keyId, { description, handler: (ctx) => void })  // keyId 如 "ctrl+g"
pi.registerFlag(name, { type: "boolean"|"string", description, default })
pi.getFlag(name) → boolean|string|undefined
pi.registerMessageRenderer(customType, renderer)
pi.registerEntryRenderer(customType, renderer)
pi.registerMarkdownTransformer(transformer)
```

工具的 `execute` 得到 `(toolCallId, params, signal?, onUpdate, ctx: ExtensionContext)`，可通过 `onUpdate` 推送 `tool_execution_update`。

### 3.3 上下文

- **ExtensionContext**（每次事件触发时创建）：`ui: ExtensionUIContext` / `mode: "tui"|"rpc"|"print"|"json"` / `hasUI` / `cwd` / `sessionManager`（只读） / `modelRegistry` / `model` / `scopedModels` / `thinkingLevel` / `isIdle()` / `isProjectTrusted()` / `signal` / `abort()` / `hasPendingMessages()` / `shutdown()` / `getContextUsage()` / `compact()` / `getSystemPrompt()` / 工具/命令/模型相关访问器。
- **ExtensionCommandContext**（命令处理器额外获得）：`waitForIdle()` / `newSession()` / `fork()` / `navigateTree()` / `switchSession()` / `reload()` / `getSystemPromptOptions()`。这些涉及 `SessionManager` 替换，需在 `withSession` 回调中完成后续工作，否则旧 `ctx` 会被 `invalidate()` 标记为 stale。

### 3.4 ExtensionUIContext（`types.ts:133-284`）

```ts
select(title, options, {signal, timeout}) → Promise<string|undefined>
confirm(title, message) → Promise<boolean>
input(title, placeholder) → Promise<string|undefined>
notify(message, type?)   → void
onTerminalInput(handler) → () => void
setStatus(key, text?) / setWorkingMessage(msg?) / setWorkingVisible(bool) / setWorkingIndicator({frames, intervalMs})
setWidget(key, content, {placement: "aboveEditor"|"belowEditor"})
setFooter(factory) / setHeader(factory)
custom<T>(factory: (tui, theme, keybindings, done) => Component, {overlay?, overlayOptions?}) → Promise<T>
setEditorComponent(factory) / getEditorComponent()
theme / getAllThemes() / getTheme(name) / setTheme(name|Theme)
getToolsExpanded() / setToolsExpanded(bool)
```

`custom` 是最强大的 UI 能力，允许扩展以 `Component & {dispose?}` 形式挂载任意 TUI 组件，并可通过 `OverlayHandle` 控制显隐。

## 4. Runner（`extensions/runner.ts`）

`ExtensionRunner` 是扩展的 **执行引擎**：

- 维护 `handlers: Map<EventType, Handler[]>` 与 `tools/commands/shortcuts/flags/renderers` 注册表。
- `emit(event)` 按注册顺序 `await` 每个 handler，捕获异常并经 `emitError({extensionPath, event, error})` 上报（单扩展异常不影响其他扩展），`fault` 时进入 `handler_error` 事件。
- `emitToolCall(event)` 支持 `input` 的**就地可变**（`event.input` mutation 链），多个 `tool_call` handler 依次改同一对象；`block` 的优先级为“任一 block 即 block”。
- `emitToolResult / emitMessageEnd / emitBeforeAgentStart` 支持返回值覆盖（后者会链式合并多个扩展对 `systemPrompt` 的修改）。
- `createCommandContext()` / `invalidate(reason)` 管理会话替换后的 ctx stale 检查。

关键不变量：**扩展异常永不崩溃主流程**，仅产出 `handler_error` 事件并继续。

## 5. 内置工具（`core/tools/*`）

八工具的 `ToolDefinition` 均含 `promptSnippet`（注入 system prompt 的 `Available tools` 段）与 `promptGuidelines`（注入 `Guidelines` 段）。执行均经 `wrapRegisteredTools()` 注入 `cwd` / `signal` / `onUpdate` / `file-mutation-queue`。

### 5.1 读写类

**read**（`tools/read.ts`）：`{ path }` → `readFile` + `truncateHead/Line/Tail`（`DEFAULT_MAX_LINES`/`DEFAULT_MAX_BYTES`）。支持大文件头/尾截断提示。

**write** / **edit**（`tools/write.ts`/`edit.ts`）：受 `withFileMutationQueue` 保护（按文件路径串行化并发写，避免竞态）。`edit` 为“精确替换”（`oldText → newText`），失败时返回带 `diff` 的错误供模型重试；`generateDiffString` / `generateUnifiedPatch` 供 TUI 着色与 Claude 风格 diff。

### 5.2 执行类

**bash**（`tools/bash.ts`）：`{ command, timeout?, workdir? }` → `BashOperations.spawn()`。默认 `createLocalBashOperations`（`node:child_process`），可被扩展替换（如 Gondolin 的远程操作）。超时时返回 `exitCode: 124`；大输出经 `truncate`。

**powershell**（`tools/powershell.ts`）：同 bash，`PowerShellOperations`。

### 5.3 检索类

**grep**（`tools/grep.ts`）：`{ pattern, path?, include?, literal? }` → `rg` 封装，`GrepToolDetails { matches: { path, line, column }[] }`。

**find**（`tools/find.ts`）：`{ pattern, path? }` → glob 封装。

**ls**（`tools/ls.ts`）：`{ path }` → `readdir`，`LsToolDetails { entries: { name, isDirectory }[] }`。

### 5.4 工具注册流

```
createAllToolDefinitions(cwd, options) → Record<ToolName, ToolDefinition>
    ↓ AgentSession._buildRuntime() 中：
       _toolRegistry = Map<name, AgentTool> (经 wrapRegisteredTool 包装，注入 cwd/signal)
       _toolDefinitions = Map<name, {definition, sourceInfo}>
       扩展 tools 同步合并（扩展 tool 可覆盖内置同名工具）
    ↓ 按 activeToolNames 过滤 → agent.state.tools
    ↓ _rebuildSystemPrompt(activeToolNames) → systemPrompt 中的工具段
```

`allowedToolNames` / `excludedToolNames` 提供进程级过滤；`initialActiveToolNames` / `setActiveToolsByName()` 提供会话级切换。`getAllTools()` / `getActiveTools()` 暴露给扩展与 TUI 的模型/工具选择器。

## 6. Skills 与 Prompt Templates

### 6.1 Skills（`core/skills.ts`）

Skill 是“可复用的 Markdown 指令块”，文件位于 `~/.pi/agent/skills/<name>/SKILL.md` 或项目 `.pi/skills/`，前端为 YAML frontmatter（`SkillFrontmatter { name, description }`），正文为 Markdown。

加载：`loadSkills(paths)` / `loadSkillsFromDir(dir)` 扫描、解析 frontmatter（`utils/frontmatter.ts`）、去重（诊断 `ResourceCollision`）。使用：

- `/skill:<name> [args]` 在 `AgentSession.prompt()` 中展开为 `<skill name="..." location="...">\n...\n</skill>\n\n<args>`（`agent-session.ts:1366-1386`），要求 `read` 或 `bash` 工具可用（否则不注入 `References are relative to ...`）。
- `formatSkillsForPrompt(skills, tool)` 将 skills 列表格式化为 system prompt 段（`buildSystemPrompt()` 调用）。

### 6.2 Prompt Templates（`core/prompt-templates.ts`）

文件式斜杠命令：`~/.pi/agent/prompts/<name>.md` 或项目 `.pi/prompts/`。`/name args` 展开为文件内容 + `args` 拼接（`expandPromptTemplate(text, templates)`）。与 `/skill:` 共享“`/` 前缀命令”预处理，但走独立展开。

## 7. 典型扩展示例

### 7.1 Gondolin（容器化）

`examples/extensions/gondolin`：覆写 `read/write/edit/bash/grep/find/ls` 的 `BashOperations`/`ReadOperations` 为“通过 QEMU micro-VM 执行”，并路由 `!` 命令到 VM；在 `session_start` 时挂载 `cwd → /workspace`。

### 7.2 Custom Provider

`examples/extensions/custom-provider-anthropic` / `custom-provider-gitlab-duo` / `llama`：

```ts
export default function(pi) {
  pi.registerProvider("my-provider", {
    baseUrl: "https://...",
    api: "anthropic-messages"|"openai-completions",
    models: [{ id, name, reasoning, input, cost, contextWindow, maxTokens, compat }],
    // 可选：apiKey / oauth / streamSimple
  });
}
```

`llama` 扩展额外展示通过 `ExtensionRunner` 的 `after_provider_response` 拦截与本地 llama.cpp 的集成。

### 7.3 拦截式审计

```ts
export default function(pi) {
  pi.on("tool_call", (e) => {
    if (e.toolName === "bash" && e.input.command.includes("rm -rf /")) {
      return { block: true, reason: "Refusing destructive command" };
    }
  });
  pi.on("tool_result", (e) => {
    e.content = [{ type:"text", text: "[audited] " + contentText(e.content) }];
  });
}
```

## 8. 设计要点

| 要点 | 做法 | 收益 |
|---|---|---|
| 工具定义用 TypeBox Schema | `parameters: Type.Object({...})` 强类型，`validateToolArguments` 运行时校验 | LLM 参数错误在执行前被拦 |
| `tool_call` 的 `input` 可变 | 多扩展链式改同一对象，无需返回值合并 | 简化多扩展协作 |
| `tool_result` 可覆盖 | `content/details/isError` 完全可替换，且会经图片归一化 | 审计/脱敏/重写灵活 |
| `before_agent_start` 链式改 systemPrompt | 多扩展依次改，后者见前者结果 | 协作式 prompt 注入 |
| 会话替换时 invalidate 旧 ctx | `_extensionRunner.invalidate(reason)` + `ctx.newSession(..., {withSession})` | 防止 stale ctx 误用新会话 |
| 危险 `rm -rf` 由扩展而非内核拦截 | `tool_call` 的 `block` 语义 | 保持内核中立，策略可插拔 |
