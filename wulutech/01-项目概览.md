# 01 — 项目概览：Pi Agent Harness

> 版本：`0.85.1`（`packages/*/package.json`） | 仓库：`earendil-works/pi` | License：MIT
> 分析时间：2026-09-16 | 分析人：OpenCode + 人工复核

---

## 1. 一句话定位

**Pi 是一套“自扩展（self-extensible）编码 Agent”的 Harness（底座）+ 多 Provider LLM 抽象 + 可编程 TUI 的 Monorepo。** 它不只是一个 CLI 聊天机器人，而是一套用于构建“能在终端里持续做事、读写文件、跑 shell、可被扩展、可远程、可持久化”的 Agent 操作系统。

- 对外暴露的产品是 `@earendil-works/pi-coding-agent`（命令 `pi`）。
- 对内拆成 11 个可单独使用的 npm 包。

## 2. Monorepo 结构

```
pi/
├── packages/
│   ├── agent/                  # @earendil-works/pi-agent-core  通用 Agent 运行时
│   ├── ai/                     # @earendil-works/pi-ai          统一多 Provider LLM API
│   ├── coding-agent/           # @earendil-works/pi-coding-agent  交互式编码 Agent CLI
│   ├── tui/                    # @earendil-works/pi-tui         差分渲染终端 UI 库
│   ├── chord/                  # @earendil-works/chord          应用组合运行时（服务/RPC/复制状态/插件）
│   ├── protocol/               # @earendil-works/pi-protocol    传输中立的 CBOR 协议
│   ├── client/                 # @earendil-works/pi-client      远程会话的传输中立客户端
│   ├── server/                 # @earendil-works/pi-server      实验性服务端
│   ├── telemetry/              # @earendil-works/pi-telemetry    厂商中立 Telemetry 契约与 Schema
│   ├── session-backends/       # 会话后端（sqlite-node 等）
│   └── evals/                  # 评测集
├── scripts/                    # 发布、校验、模型数据生成等
├── .pi/skills/                 # 项目级 Skills
└── wulutech/                   # ← 本文档集落盘位置
```

`package.json:5-13` 定义了 workspace，`packages/coding-agent/examples/extensions/*` 也被纳入 workspace 以便联调。

## 3. 各 Package 职责速览

| Package | npm 名 | 一句话职责 |
|---|---|---|
| `agent` | `pi-agent-core` | **通用 Agent 运行时**：`Agent` 类 + `agent-loop` + `AgentHarness`（持久化、分支、压缩）+ 工具抽象。多用于被 `coding-agent` 复用，也可独立用于自定义 Agent。 |
| `ai` | `pi-ai` | **统一 LLM 抽象层**：`Model<TApi>` 统一模型定义、`Context`/`Message` 统一消息、`ProviderStreams` 统一流、`Models`/`ModelStore` 统一发现与鉴权。覆盖 30+ Provider、10 种 API（`openai-completions` / `anthropic-messages` / `google-generative-ai` 等，见 `packages/ai/src/types.ts:17-28`）。 |
| `coding-agent` | `pi-coding-agent` | **交互式编码 Agent CLI**：`pi` 二进制入口、`AgentSession` 会话编排、`read/bash/edit/write/grep/find/ls/powershell` 8 工具、扩展系统、Skills、Sessions、TUI/RPC/Print 三种运行模式。 |
| `tui` | `pi-tui` | **终端 UI 库**：差分渲染、布局（VStack/HStack/Box 等）、`Editor`/`SelectList`/`Markdown`/`ScrollView` 组件、`TuiMainScreen`/`TuiAltScreen` 双模式、`keys.ts` 统一键盘、原生剪贴板/图片（Kitty/iTerm2/Sixel）支持。 |
| `chord` | `chord` | **应用组合运行时**：`Facet` 插件模型 + `replicatedState` 复制状态 + `RemoteService` RPC + `ServiceProvider` 发布/订阅。Pi 用它来组装复杂应用。 |
| `protocol` | `pi-protocol` | **传输中立 CBOR 协议**：`PROTOCOL_VERSION=8`，`hello` 握手、`request`/`response`/`cancel` 信封、`service_update`/`attachment` 带外更新，CBOR 编码 + 帧封装（`packages/protocol/src/cbor` + `framing.ts`）。 |
| `client` / `server` | `pi-client` / `pi-server` | **远程会话的传输层**：Client 通过 framed CBOR bytes 与 Server 的 `SessionRouter` 会话路由通信；支持 Unix Socket（`packages/client/src/unix.ts`、`packages/server/src/transports/unix`）。 |
| `telemetry` | `pi-telemetry` | **可观测性契约**：`defineTelemetrySchema` 定义 Span/Event 的强类型 Schema，`InMemoryTelemetryContext` / `NOOP` 两种实现，一致性测试套件。`agent`/`ai` 均依赖它产出结构化遥测。 |
| `session-backends/sqlite-node` | `pi-session-backend-sqlite-node` | **会话存储后端**：Node SQLite 实现 `Storage` 接口，支撑 `agent` 的 `Session` 持久化。 |

关系链（简化）：

```
用户 ←→ TUI ←→ coding-agent (AgentSession) ←→ agent (Agent / AgentHarness / Session)
                      ↕                              ↕
                   ai (Models / Providers / Auth)   telemetry / chord / protocol
```

## 4. 设计哲学（从代码与文档中提炼）

1. **Harness > Chatbot**：`AgentHarness`（`packages/agent/src/harness/runtime/harness.ts`）把“会话、分支、压缩、重试、队列、持久化”做成可复用的底座，而 `Agent`（`packages/agent/src/agent.ts`）只负责“单次 Run 的循环与事件”。`coding-agent` 在此之上做产品化。
2. **自扩展优先**：扩展是“一等公民”（`packages/coding-agent/src/core/extensions/`），可注册工具、命令、快捷键、UI 覆盖、生命周期钩子，并能拦截 `tool_call`/`tool_result`/`before_agent_start` 等。允许用户把任意 TS 模块变成 Pi 的一部分。
3. **Provider 中立**：`pi-ai` 用 `Api` 维度（`openai-completions` 等）而非 Provider 维度组织能力，同一 API 多 Provider 共享实现；`Model` 定义包含 `cost`/`contextWindow`/`reasoning`/`thinkingLevelMap`/`compat` 等细粒度元数据，`models.generated.ts` 由 `scripts/generate-models.ts` 生成，不允许手改。
4. **会话即文件系统**：会话被建模为 **DAG + 分支**（`Entry` + `branchTip`），`SessionManager`（`packages/coding-agent/src/core/session-manager.ts`，1746 行）维护 `SessionHeader` + `SessionEntry` 的 JSONL 追加日志，天然支持 fork / navigate / branch summary / compaction。
5. **工程化克制**：`AGENTS.md` 明确“无 `any`、无内联导入、erasable TS、pinned 依赖、shrinkwrap、check 流水线”等约束；`npm run check`（`package.json:21`）是提交门禁。

## 5. 入口与构建

- 构建：`npm run build`（按 `chord → tui → telemetry → ai → agent → session-backends → protocol → client → server → coding-agent` 顺序，`package.json:16`）或 `build:offline`（复用已抓取的模型数据）。
- 校验：`npm run check` = `biome check --write` + `check:pinned-deps` + `check:runtime-deps` + `check:ts-imports` + `check:entry-graphs` + `check:shrinkwrap` + `check:install-lock` + `tsgo --noEmit` + `check:browser-smoke`。
- 测试：`./test.sh`（跳过需 API Key 的 LLM 测试）；单文件 `node $(git rev-parse --show-toplevel)/node_modules/vitest/dist/cli.js --run test/specific.test.ts`。
- 运行：`./pi-test.sh`（从源码运行 `pi`，可在任意目录执行）。

## 6. 版本与发布

- 采用 `npm version --workspaces` 同步 bump + `scripts/sync-versions.js` 同步跨包版本；发布脚本 `scripts/publish.mjs` / `scripts/release.mjs` / `scripts/local-release.mjs`。
- 二进制：`scripts/build-binaries.sh`，发布产物为 `pi-<version>-source.tar.gz` + `SHA256SUMS`，支持 `--offline-model-data` 离线模型数据构建。
- 供应链硬化（`README.md:77-90`）：`save-exact=true`、`min-release-age=2`、`package-lock.json` 为真源、`npm-shrinkwrap.json` 锁定传递依赖、`--ignore-scripts` 安装、`npm audit` 定时任务、生命周期脚本显式 allowlist。
